# Files Markdown 预览配色修复

日期：2026-09-28。

## 问题与修复

Files 已继承应用深浅主题，但 Markdown 阅读区仍固定白底，分区标题仍固定浅色渐变。深色主题的浅灰文字因此落在白底上；浏览器实测旧版正文对比度约 1.18:1。

本次只把阅读区背景改为 `var(--bg)`、分区标题背景改为 `var(--bg-soft)`。背景和现有文字配色一起随主题变化，不更改字体、布局、Markdown 渲染、文件权限或终端状态。

修改文件：

- `static/index.html`：两处背景颜色。
- `tests/ui_browser.mjs`：实际 Files 打开／渲染路径的配色回归。
- 本报告。

## 验证

新浏览器测试在旧版上复现低对比度失败，修复后通过。覆盖正文、标题、引用、行内代码、代码块、表格、链接和 Files 分区标题；深色、浅色、跟随系统深色／浅色均要求对比度不低于 4.5:1。样本最低值分别为深色 6.98:1、浅色 5.90:1；解析器不可用时的纯文本回退也验证了深浅主题。

浏览器测试使用独立 Edge 配置、样本 API 及固定 Markdown 渲染结果，不依赖外部 CDN，也不访问真实会话。它验证样式与预览集成，不替代第三方解析器或 iOS 真机测试。深浅主题截图已人工查看，主题切换没有重载终端 iframe。

完整 Python unittest **264/264 通过**，Python 3.13.5，warnings-as-errors，无跳过。完整 UI 浏览器回归、Python 编译、逐文件 shell 语法、JSON、inline JS、浏览器脚本语法和 diff 检查通过。独立 Terminal 创建／接入／输入／停止冒烟通过，未操作用户 Agent。
