# SiLing UI/UX 优化规格

状态：Draft，待按阶段实施。本文是目标规格，不代表所述功能已经实现。

## 1. 目标与范围

让用户在多个 agent 并行运行时，快速识别任务、判断是否需要介入，并在桌面与手机上完成查看、输入和恢复工作。

本轮覆盖信息架构、视觉规范、agent 身份、pane 操作、移动端、Settings、通知与错误反馈。保留现有 session、tmux、远程节点和终端交互能力，采用分阶段替换；前端框架迁移、原生手机 App、重新实现终端模拟器不属于本轮范围。

### 核心使用场景

1. 桌面同时查看 6–12 个 session，找到等待输入或异常的任务。
2. 从指定空 pane 创建 session，完成输入、查看文件和放大阅读。
3. 手机上查看进度、处理待办，必要时进入一个交互终端。
4. 修改默认目录、外观和通知策略，并理解设置影响范围。
5. 遇到断连或更新阻塞时，直接看到原因和下一步操作。

## 2. 现状依据

本规格基于 README、仓库截图、`static/index.html`、Dashboard 后端及相关测试的审查。截图包含历史版本，以当前代码为行为依据。尚未完成手机真机可用性测试，键盘遮挡、触摸冲突和性能需在实施时验证。

| 当前实现 | 用户影响 | 对应需求 |
| --- | --- | --- |
| 顶部常驻主题、恢复、更新及十种布局入口，窄屏横向滚动 | 高频入口难定位 | NAV-01 |
| 窄 pane 标题占约三分之一，操作区裁切 | 任务难辨认，操作可能不可见 | PANE-01 |
| agent 身份未在侧边栏和 pane 中统一展示 | 依赖终端内容辨认 agent | AGENT-01 |
| Lead、优先级和人工状态共用标记控件 | 角色、优先级、运行状态混淆 | STATE-01 |
| 手机主要将网格改为单列，iframe 抢占触摸手势 | 多任务切换和滚动困难 | MOBILE-01 |
| Files 使用桌面分栏和较大的侧栏宽度 | 手机预览空间不足 | FILE-01 |
| Settings 只有链接打开方式和背景不透明度 | 配置分散、范围不明确 | SETTINGS-01 |
| 更新阻塞原因主要放在 title，较多反馈使用 alert | 手机难查看原因，操作被打断 | FEEDBACK-01 |

## 3. 设计原则

- 任务名称与待处理状态优先，低频操作渐进展开。
- agent 身份、优先级、运行状态、连接状态分别表达。
- 颜色必须配合文字或形状，关键含义不能只靠颜色。
- 桌面支持高密度并行工作；手机优先单任务阅读和处理。
- UI 布局变化不得意外重启 session、丢失输入或重连终端。
- 页面反馈明确区分请求成功、后台执行中和最终完成。

## 4. 信息架构与桌面布局

### NAV-01：主导航与工具栏

- 一级目的地为「工作台」「待处理」「项目与文件」；Settings 使用固定、可见的入口。
- 现有 Mission Control 复用为概览与待处理能力的基础，避免再建一套重复状态面板。
- 顶部主要操作为新建、搜索、视图/布局；保存恢复放入工作区菜单，主题、提醒策略和更新归入 Settings。
- 布局选择器使用网格缩略图和名称，保留所有现有布局；允许收藏常用布局。
- 地址栏收为连接状态入口，展开后提供地址复制和手机访问说明；含凭据的地址默认遮蔽敏感部分。
- 侧边栏支持按项目或节点分组，以及 agent、状态、优先级筛选；保持当前分组默认值，记住用户选择。

验收：在 1280px 桌面宽度下，高频操作无需横向滚动；已有布局均可选择；设置与新建入口始终可发现。

### PANE-01：pane 标题与操作

- 标题区域优先显示 agent 标识、任务名称、状态；节点与模型为次级信息。
- 常驻操作为文件、放大、更多；窄 pane 可将文件收入更多菜单。
- 重连、主题、移动位置、关闭 pane、终止 session 放入分组菜单。
- 「关闭 pane」说明 session 继续运行；「终止 session」说明停止执行并保留哪些恢复信息。
- 全部操作必须有可达入口，禁止通过 overflow 裁切作为唯一窄屏策略。
- 空 pane 支持点击、Enter/Space 新建，并保留目标位置。请求期间目标被占用或布局改变时，不覆盖其他 session；使用其他空位，或明确提示从列表打开。
- 新建中的占位显示启动状态，库存尚未刷新时保留预约位置；失败后显示重试入口。
- 保留拖放，并提供「移动到 pane…」作为键盘和触屏替代。

验收：在 320px pane 宽度下仍能识别任务并访问所有操作；移动、放大和改变密度不导致无关终端重连；创建失败不破坏原有布局。

## 5. 视觉与 agent 身份

### VISUAL-01：统一视觉基础

- 建立语义化颜色、间距、字号、圆角、阴影、层级和焦点样式变量。
- 支持系统、深色、浅色主题；Files、Settings、菜单与主工作台统一。终端配色允许独立选择。
- 提供舒适、紧凑两种密度。常规正文建议 14px，次级信息 12px；终端字号单独设置。
- 通用操作采用统一 SVG 图标体系，建议按需打包 Lucide；不依赖运行时 CDN。
- 关键或不直观的操作保留文字；纯图标按钮必须有可访问名称。
- 中文与英文使用统一文案映射，语言默认跟随浏览器，可手动选择；第一阶段先整理所修改页面的文案。
- 动画仅用于反馈变化；支持减少动画，避免多个运行中 pane 持续闪烁。
- 「背景不透明度」明确 100% 为完全不透明。仅在指定容器背景应用一次透明效果，避免多层背景 alpha 叠加；文字和控制器不整体变淡。

### AGENT-01：身份规范

| 类型 | 展示 | 色彩方向（提案） |
| --- | --- | --- |
| Claude Code | 专属标识＋Claude | 暖色局部装饰 |
| Codex | 专属标识＋Codex | 冷色局部装饰 |
| Cursor Agent | 专属标识＋Cursor | 中性色局部装饰 |
| Terminal | 终端符号＋Terminal | 灰色 |
| 未知 agent | 通用标识＋原始名称 | 中性色 |

上述色彩不是官方品牌规范。品牌素材实施前核对来源、授权和深浅主题表现；无合适素材时使用文字徽标。身份色限于徽标等局部区域，不占用错误和待处理的语义色。

验收：侧边栏、pane、新建选择器、详情和通知使用相同身份组件；不阅读终端输出即可识别 agent；未知类型有正常回退。

## 6. 状态与待处理

### STATE-01：分离状态维度

| 维度 | 示例 | 来源 |
| --- | --- | --- |
| 角色 | Lead、普通 | 人工配置 |
| 优先级 | P0 紧急、P1 重要、P2 普通、未设置 | 人工配置 |
| 执行状态 | 运行中、等待输入、已退出、未知 | agent 生命周期与现有检测 |
| 人工标记 | 关注、阻塞、完成 | 用户操作 |
| 连接状态 | 在线、重连中、离线 | Dashboard/节点/终端连接 |

第一阶段解释并改善现有 `panel_state` 的呈现，不改变其存储语义。第三阶段如需允许角色、优先级和标记同时设置，需增加独立字段与迁移方案：保留原值，确保旧客户端和 CLI 兼容，并测试迁移回退。

### STATE-02：待处理中心

- 汇总等待输入、执行失败、未读结果及状态过期的 session。
- 每项显示任务、agent、原因、最后更新时间和可执行入口。
- 区分最后收到状态、最后输出及最后有效心跳；无可靠信号时显示未知。
- 五分钟监控场景展示最后心跳与预期下一次时间；只在存在明确心跳约定时标记逾期，不将终端静默直接判为卡死。
- 查看结果后的已读规则与现有通知确认机制一致；去重同一事件。

验收：离线不会显示为任务完成；无输出不会直接显示失败；用户能从待处理项一步进入对应 session。

## 7. 手机体验

### MOBILE-01：导航与阅读

- 默认入口为任务列表，提供待处理、全部任务筛选以及可见的新建入口。
- 点击任务进入单 session 详情，包含输出、文件、信息三个视图；返回后恢复列表筛选与位置。
- 手机默认只呈现一个交互终端。切换终端时管理 iframe 与连接生命周期，后台 tmux session 保持运行。
- 阅读模式显示终端输出片段并标明更新时间；显式「进入终端」切换交互模式，提供清晰的退出入口。
- 输出片段不得伪装为结构化对话；未经实现和验证，不宣称能可靠提取所有 agent 的语义进度。
- 保留现有桌面布局偏好，手机导航不覆盖它。

### MOBILE-02：输入与触摸

- 输入框支持多行、明确发送按钮和草稿保留。不同 session 草稿隔离。
- 提供 Esc、Tab、Ctrl+C 等辅助键；发送后给出明确反馈。
- 软键盘弹出时输入区与发送按钮可见；适配动态视口、横竖屏和安全区。
- 主要触控区域目标为至少 44×44 CSS px；不把 hover、双击或拖拽作为唯一入口。
- 断线期间保留草稿，禁止静默丢弃或不明确地重复发送。

### FILE-01：文件导航

- 桌面保留可调整分栏；手机改为目录列表与文件预览的逐级导航。
- 预览提供返回、路径与外部打开入口；目录、Markdown、源码和图片均可查看。
- 页面本身无非必要横向滚动；宽代码、表格和终端可在自身区域内滚动。

验收：在 360、390、430px 宽度和横屏下完成「查看待处理→打开任务→输入→查看文件→返回」；iOS Safari/PWA、Android Chrome 分别真机验证滚动、键盘和后台恢复。

## 8. Settings

### SETTINGS-01：分组与范围

| 分组 | 配置内容 |
| --- | --- |
| 外观 | 主题、密度、界面字号、不透明度、减少动画、语言 |
| 新建 session | 默认 agent、工作目录、启动方式、各 agent 默认参数 |
| 终端与输入 | 字体与字号、配色、发送/换行方式、快捷键说明 |
| 通知与监控 | 权限状态、事件类型、提醒间隔、心跳说明 |
| 浏览与文件 | 内部/外部打开、预览偏好 |
| 连接与更新 | 节点状态、版本、更新验证结果、阻塞原因和诊断 |

- 每项明确标注影响范围：此浏览器、此服务、当前 session。
- 浏览器外观偏好即时预览并持久化；服务配置使用明确的保存动作，失败时保留输入并说明原因。
- 桌面采用分组导航＋内容区；手机采用分组列表＋详情页。分组较多时支持设置搜索。
- `~/Workflows` 作为默认目录逻辑继续保留，可通过设置修改；远程目录在远程节点校验。
- 环境变量覆盖的值显示其来源；不能出现 UI 保存成功但有效值未改变的假象。
- 提供分组恢复默认值；变更需要重启时明确说明。单 session 设置不能误应用到所有 session。

### SETTINGS-02：持久化与后端边界

- 复用既有 localStorage key；新增偏好集中管理，非法或旧值安全回退。
- 服务级配置需要专用、认证保护、字段白名单的接口；返回有效值、来源和是否可编辑。
- 保存采用原子写入，保留未知配置字段，避免覆盖其他节点及现有配置。
- 默认目录需验证存在性及可用性，不在保存偏好时自动创建任意目录。
- 凭据不通过通用设置读取接口回传；敏感信息与普通偏好分开处理。
- 浏览器偏好不承诺跨设备同步；节点配置明确指向实际服务。

验收：修改后刷新仍生效；保存失败不显示成功；环境覆盖、非法路径、远程离线和旧配置均有明确结果。

## 9. 反馈、更新与可访问性

### FEEDBACK-01：操作反馈

- 成功操作使用 toast；字段错误就地显示；断连和更新阻塞使用持续可见的状态区。
- 更新详情展示当前/目标版本、检查与测试阶段、失败或阻塞原因、重试入口；保留现有验证后应用流程。
- 移除对 `title` 的关键说明依赖，手机也能展开详情。
- 危险操作使用具体动词并说明影响；保留执行中的防重复提交与失败恢复。

### A11Y-01：交互基线

- 弹窗具备名称与语义；打开后移动焦点、限制 Tab 范围，关闭后恢复到触发位置。
- 多层弹窗只由最上层处理 Escape；背景不可误操作。
- 图标按钮、筛选器、展开控件和状态更新提供相应可访问属性。
- 普通文本目标对比度至少 4.5:1；焦点可见，状态不只依赖颜色。
- 支持键盘完成新建、切换任务、打开文件、修改设置；拖放有替代操作。

## 10. 实施阶段与依赖

### 改版前置回归问题

- Terminal 普通拖选必须产生可复制文本，并保留终端程序所需的鼠标操作入口。
- Codex 新建与恢复必须使用可保留滚动历史的启动模式；说明旧 session 的历史限制。
- Codex 浏览历史后直接打字或粘贴应返回实时终端，首字符不得丢失；滚动、复制不得误退出历史。
- 窄 pane 的长标题不得遮挡优先级下拉框，其余操作必须可达。
- spec/报告交付时绑定到 Files；跨行 URL 的可见分段应同时高亮，点击任一分段打开完整目标。
- 上述行为应纳入后续视觉改版的回归验证。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| A：视觉与桌面基础 | 主题变量、SVG 图标、agent 徽标、pane 菜单、工具栏整理、Settings 外观页 | 高频路径可达，窄 pane 可用，现有终端行为无回归 |
| B：手机核心路径 | 任务列表、单 session 详情、输入区、文件单列导航 | 两类手机浏览器真机流程通过，后台恢复与键盘验证完成 |
| C：状态与配置完善 | 待处理中心、状态解释、服务级设置、更新诊断 | 状态来源明确，配置保存可靠，迁移与旧客户端兼容 |

阶段 A 同时验证手机低保真原型，避免桌面组件阻碍后续适配。状态字段迁移和设置写入接口分别作为可独立审查的变更。

## 11. 工程约束与验证

- 从现有单文件前端逐步提取公共样式、图标、菜单、弹窗和设置逻辑，不以框架迁移作为前提。
- 保留现有 session ID、远程标识、布局和恢复数据；对 iframe 节点移动、焦点和缓存保持谨慎。
- 新增行为测试覆盖真实交互和持久化，不以源码字符串存在作为主要验收证据。
- 浏览器验证至少覆盖 1440×900、1280×800、768×1024、390×844；测试数据包含本地/远程、不同 agent、长任务名、离线与未知状态。
- 验证四条核心路径：空 pane 新建并定位；多 pane 切换/放大；手机输入及文件返回；设置保存及失败恢复。
- 性能对比使用同一设备、相同 session 数和同一数据集，记录连接数、内存与交互表现；手机的阅读模式不为每个列表项创建终端 iframe。
- 实施提交运行完整 unittest、Python/Shell/JSON 校验、内联 JS 语法检查，并做真实 session 创建、挂载、发送、停止冒烟。
- 每阶段提供桌面与手机前后截图、已知限制、回退方式；用户操作文档变更同步更新中英文 README。
